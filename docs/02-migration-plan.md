# MM リプレイス移行計画

## 1. 移行方針

- 方式: 一括移行
- 許容停止: 30 分以内
- 維持要件:
  - LINE/LIFF 導線（リッチメニュー → LIFF 起動 → 利用）
  - データ更新時の対象ユーザー通知
- データ基盤: Spreadsheet 継続

## 2. 全体マイルストーン

1. 現状棚卸し
2. 設計確定（本ドキュメント + 実装ガイド）
3. 実装・単体検証
4. 統合検証・リハーサル
5. 本番切替
6. 安定化確認

## 3. フェーズ詳細

## Phase A: 現状棚卸し

- 既存 API 一覧（パラメータ、レスポンス、エラー）
- GAS ジョブ一覧（実行頻度、依存データ、失敗時挙動）
- LINE 通知一覧（トリガー、宛先、本文テンプレート）
- Spreadsheet スキーマ一覧（シート、列、型、制約）

### 完了条件

- 上記一覧が作成され、欠損項目がない。

## Phase B: 新基盤実装

- Hono API 実装（既存互換優先）
- Spreadsheet Repository 実装
- LINE 通知アダプタ実装
- Workers Cron への GAS 処理移植

### 完了条件

- 主要ユースケース（Expense CRUD + 月次一覧）が新基盤で動作する。

## Phase C: LIFF 側接続

- API クライアントを新エンドポイントへ切替
- 画面導線を再設計（ただし LINE 起点は維持）
- 必要箇所の型共有化（OpenAPI 由来）

### 完了条件

- LIFF 主要導線で業務操作が完了できる。

## Phase D: 総合リハーサル

- 本番相当データで切替手順を時系列で実施
- 通知トリガーと配信結果を検証
- 毎月5日 19:00（JST）/ `0 10 5 * *`（UTC）の先月精算通知ジョブを検証
- 30 分以内で切替可能か計測

### 完了条件

- Go/No-Go 判定を満たす。

## Phase E: 本番切替

- メンテナンス開始告知
- 旧 API 停止
- 新 API/Job 有効化
- LIFF 参照先切替
- スモークテスト

### 完了条件

- 重大障害なしでサービス再開。

## 4. Go/No-Go チェックリスト

- OpenAPI と実装が一致している。
- Expense CRUD / 月次一覧 / 更新通知 / 先月精算通知がすべて成功する。
- 通知重複送信が発生しない。
- 切替ランブックをリハーサル済み。
- ロールバック手順を検証済み。

## 5. ロールバック計画

1. LIFF 参照先を旧 API に戻す。
2. 新 API への書き込みを停止する。
3. 切替中の更新差分を確認し、必要なら手動同期する。
4. 旧ジョブ（GAS）を再開する。
5. 利用者へ切戻し完了を通知する。

## 6. 切替当日ランブック（30分）

- T-10: 事前確認（環境変数、Secrets、疎通）
- T+00: メンテ開始、旧 API 停止
- T+05: 新 API デプロイ有効化
- T+10: LIFF 設定切替
- T+15: スモークテスト（Expense CRUD、一覧、更新通知、先月精算通知）
- T+25: 判定（継続 or ロールバック）
- T+30: メンテ終了告知

## 7. 体制（個人運用向け）

- 実装責任: 1名
- 事前自動化: 手順書とチェック項目を先に固定
- 障害時優先順位:
  1. 誤通知防止
  2. データ整合性維持
  3. UI 復旧

## 8. 将来拡張バックログ（初期スコープ外）

- 精算完了時に相手ユーザーへ通知する機能
- 精算額を再確認するための手動通知機能
